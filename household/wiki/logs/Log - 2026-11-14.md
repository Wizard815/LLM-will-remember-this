# Log - 2026-11-14

## Actions

### Dashboard fix
- **Installed the Dataview plugin (v0.5.68)** — `HOME.md`, [[Homelab]] and other area hubs have used ` ```dataview ``` ` query blocks since the 2026-10-27 PARA rebuild, but the plugin was never actually installed. Those blocks were rendering as plain text. Added `.obsidian/plugins/dataview/` and enabled it in `community-plugins.json`.

### Embedding model swap
- Switched the Second Brain extension's embedding model from `nomic-ai/nomic-embed-text-v1.5` to `onnx-community/Qwen3-Embedding-0.6B-ONNX` (set via the `custom` model option), to use a stronger, more current retrieval model.
- Cleared `cachedModelName` so the extension detects the mismatch and rebuilds its embedding index from scratch on next load.
> [!warning] Verify
> This is a config change made against the git clone, not the live container. On RaidLab: pull this branch, restart the `LLMWIKI` container (or reload the plugin), and re-run `query_wiki` to confirm the new model downloads and loads cleanly — `@huggingface/transformers` bundled in the plugin already has Qwen3-architecture support, but the actual load has not been verified on the real instance yet. If it fails to load, revert `modelName`/`customModelName`/`cachedModelName` to the prior Nomic values.

### Git noise cleanup
- Set `obsidian-git`'s `autoSaveInterval` to `0`, disabling the 10-minute timer-based auto-commit. Git log was almost entirely `auto: <timestamp> (N files)` commits instead of the `ingest:`/`maintain:`/`lint:`/`manual:` convention in [[agents]] rule 5. Agents/humans should commit explicitly after each batch going forward.

Decision: hold it in reserve as the candidate engine for a future short-term/working-memory auto-ingest tier (separate from the curated PARA wiki) rather than delete it outright. Plugin files and its Argos-backed config (`qwen3.5-2b-q5_k_s`) are untouched on disk if that design goes ahead; if not, remove the plugin folder in a later cleanup.
